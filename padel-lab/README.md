# Padel Lab

Put a phone on a tripod behind the court, record the match, load the video.
You get, per player, a position heatmap and the share of time at the net, plus
rally count and rally lengths, and a match log that tracks those against your
level over time.

Everything runs in the browser. The video never leaves the device, there is no
backend, and the match log is kept in `localStorage` (with JSON export/import).

## How it works

1. **Calibrate.** You place four known floor points (by default where the two
   service lines meet the side walls), with a magnifier for precision. That
   gives a homography from image pixels to court metres.
2. **Track players.** The video plays at up to 4× while frames are sampled
   about five times per second of footage.
   - A person detector (MediaPipe EfficientDet-Lite) runs on crops, never the
     whole frame: court-following tiles to find players, then a zoomed crop
     around each player already being followed. The app benchmarks the device
     and uses the larger Lite2 model where the GPU can afford it.
   - Each box's bottom-centre is projected onto the floor; anything off the
     court is dropped.
   - Four tracks (two per side) run a constant-velocity filter. Detections are
     assigned to tracks all at once, by distance from the predicted position
     plus shirt-colour difference, with hard limits: no teleporting, no
     crossing the net.
   - Tracks are then resampled, short occlusions bridged, and smoothed.
3. **Hear the hits.** The soundtrack goes through an audio worklet that
   measures high-passed energy. Sharp peaks above the local background are
   candidates; the loudness threshold is picked from the recording itself
   (Otsu split between own-court impacts and quieter noise) and can be
   overridden. Hits closer than 4.5 s apart form a rally.
4. **Analyse.**
   - Per player: heatmap (0.5 m cells), zone split (net = within 4 m of the
     net, transition = 4–7 m, back = beyond), net approaches, distance, top
     speed, court side.
   - Per pair: both at the net / one up one back / both back, partner spacing.
   - Rallies: count, lengths, tempo, rest, share of time in play, a timeline.
   - Plain-language takeaways, generated by rules from those numbers.
5. **Review.** Watch the video back with a live top-down view of all four
   players, and jump straight to any rally.

## Known limits

- **No ball tracking** (v2). Shot types, winners and errors are out of scope.
- "Hits per rally" counts loud impacts, so hard bounces off the glass inflate it.
  Rally count and duration are the dependable numbers.
- Partners in near-identical kit can still swap identities after crossing closely.
- A near-side player whose feet are below the frame is placed a little too deep.
- Speed and distance are estimates; far-side figures are noisier.
- The camera must not move after calibration.
- The video has to be in a format the browser can play. iPhone HEVC plays in
  Safari and recent Chrome; otherwise export as H.264 MP4.
- Analysis pauses while the tab is hidden.
- Tracks and the video are not saved, only the computed numbers. Review is
  available right after an analysis.

## Develop

```bash
npm install
```

```bash
npm run dev
```

```bash
npm test
```

```bash
npm run build
```

`npm run dev` and `npm run build` first copy the MediaPipe WASM runtime from
`node_modules` into `public/mediapipe/` (git-ignored). The detector model is
fetched from Google's MediaPipe model bucket at run time. `?model=fast` or
`?model=accurate` and `?delegate=cpu` override the automatic choice.

## Layout

- `src/lib/court.ts` court dimensions, zones, calibration presets
- `src/lib/homography.ts` image ↔ court mapping
- `src/lib/tiles.ts`, `detector.ts` court-following crops and the person detector
- `src/lib/tracker.ts`, `stats.ts` four player tracks and their numbers
- `src/lib/audio.ts`, `hits.ts`, `public/hit-envelope.worklet.js` hit and rally detection
- `src/lib/analyzer.ts` the playback loop tying it together
- `src/lib/insights.ts` rule-based takeaways
- `src/lib/store.ts` match log
- `src/components/` screens and charts
